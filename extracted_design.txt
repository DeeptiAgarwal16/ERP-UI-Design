MASTER PROJECT PROMPT: GNV COMMODITIES PVT. LTD. — COMPLETE ERP OPERATIONS MANAGEMENT SYSTEM
Act as a senior ERP architect, product designer, full-stack developer, inventory management specialist, and business process analyst.
Build a complete, modern, highly interactive ERP web application for GNV Commodities Pvt. Ltd., a business using Zoho Books for its sales, inventory, pricing, and order fulfilment operations.
The application must cover the complete business lifecycle: product management, customer management, discount configuration, sales order punching, warehouse allocation, batch and expiry management, child sales order creation, inventory inward, inter-warehouse transfers, invoicing, packaging, shipment, dispatch, and delivery.
This must be a working, navigable application with realistic dummy data and functional frontend interactions, not just a static dashboard, landing page, or visual mockup.
The most important requirements are:
An exceptionally polished, professional, bright, light-theme blue UI.
A simple, self-explanatory interface that warehouse employees with limited technical knowledge can use confidently.
Correct implementation of the business logic for allocation, discounts, FEFO, inventory, and order splitting.
A unique GNV Number that groups all sales orders created from the same original order during allocation.
A modular architecture ready for a Python FastAPI backend and future Zoho Books API integration.

7. GNV NUMBER — LINKED ORDER GROUPING SYSTEM
This is a critical business requirement.
When one original sales order is split into multiple warehouse sales orders during allocation, every resulting order must be identifiable as part of the same original customer order.
Implement a GNV Number, which acts as a unique parent-order grouping identifier.
GNV Number Rules
Assign a unique GNV Number to each original customer sales order when it is first created or submitted for processing.
Use a readable demo format such as GNV-2026-000001, GNV-2026-000002, and so on.
Generate unique sequential demo numbers and prevent duplicates.
The GNV Number is not a replacement for the individual sales order number.
Every child warehouse sales order generated from the same parent must carry the same GNV Number.
The Balance SSO must carry the same GNV Number.
All invoices, packages, and shipments must retain references to their source sales orders and GNV Number wherever applicable.
Never generate a different GNV Number for child orders belonging to the same parent order.
Preserve the GNV Number when a draft is edited or the order moves through its lifecycle.
Use a separate unique identifier for each child sales order.
Example:
Original Sales Order: SO-10025
GNV Number: GNV-2026-000001
Allocation creates:
SO-10025-CHN — Chennai
SO-10025-MUM — Mumbai
SO-10025-NOI — Noida
SO-10025-KOL — Kolkata
SO-10025-BAL — Balance SSO
All five records must display:
GNV Number: GNV-2026-000001
The child sales order numbers above are illustrative demo identifiers.
